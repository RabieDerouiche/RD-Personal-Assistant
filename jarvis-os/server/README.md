# Serveur JARVIS OS (phase 3)

Fait tourner Claude Code (`claude -p`, programme officiel) avec l'abonnement Claude du propriétaire, sur son propre serveur, pour lui seul. Aucune clé d'API : `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL` et les variables Bedrock / Vertex / Foundry sont retirées avant chaque appel (elles feraient payer l'API).

- `server.mjs` : Node 22, sans dépendance. API : `/api/health`, `/api/pair` (code à usage unique, 30 min), puis avec le jeton : `/api/status`, `/api/state`, `/api/chat` (flux SSE), `/api/missions/:id`, `/api/import`, `/api/memory`. Sert aussi l'app (`../web`).
- Discussion : Claude avec le web seulement (WebSearch, WebFetch), sans commande système ni écriture. Une demande pour un agent devient une mission « à approuver » (ligne `MISSIONS:` retirée de la réponse lue).
- Missions approuvées pour Claude : faites sur le serveur (web, lecture et écriture dans un dossier de travail par mission, sans commande système), compte rendu dans la mission. Bots Grok : phase 4.
- **Accès Google direct (0.10.0)** : `google.mjs`. Le propriétaire crée un identifiant OAuth « Application Web » (redirection `https://<serveur>/api/google/callback`) et le colle dans JARVIS (Réglages) ; le serveur garde l'identifiant, le secret et le jeton durable dans `state.json` (droits 600, jamais renvoyés). API avec le jeton de l'appareil : `GET /api/google` (état, adresse de redirection), `POST /api/google/config`, `POST /api/google/link` (adresse de consentement, état à usage unique 10 min), `POST /api/google/unlink` (jeton révoqué) ; `/api/google/callback` (retour de Google, protégé par l'état). `POST /api/tool {server, tool, input}` traduit les outils de la page Jarvis (Google Sheets `get_values`, `append_values`, `update_values` ; Google Calendar `list_events`, `create_event`, `update_event`, `delete_event` ; Gmail `search_threads`, `get_thread`, `list_drafts`, `send_message`, `delete_draft`, `unlabel_thread`) en appels aux API Google, avec des réponses de la forme des connecteurs claude.ai. Erreurs : `server_not_connected` (pas relié), `needs_reauth` (accès retiré), `not_granted`, `tool_error`, `not_in_manifest`. Portées : spreadsheets, calendar.events, calendar.readonly, gmail.modify, drive.readonly.
- `POST /api/sample` : Claude ponctuel pour la page (aide à la décision, discussion), sans aucun outil, hors de la conversation vocale. Depuis 0.11.0, la consigne peut décrire les outils de la page : Claude écrit ses propositions en fin de réponse (`⟦outil nom {json}⟧`), le pont `jarvis-serveur.js` les retire du texte et les passe à la page, qui les affiche avec leur bouton (rien ne part sans son appui). **Depuis 0.30.0 (Claude instantané, `flux.mjs`)** : `stream: true` rend la réponse mot par mot (SSE : `ouvert`, `delta {d}`, `done {text, premier, total, secours}`, `error {message}`), finie au dernier mot ; `conv: true` (la discussion) garde le Claude de la discussion ouvert, un par modèle : les questions suivantes n'envoient que la question (l'heure de Paris en tête), le reste est relu dans le cache ; consigne de Claude Code remplacée (`--system-prompt`), aucun outil intégré (`--tools ""`), aucun connecteur (`--strict-mcp-config`), secours `--fallback-model` (Haiku → Sonnet, Sonnet → Haiku, Opus → Sonnet ; `JARVIS_SECOURS=0` pour couper) ; file à part (deux questions ponctuelles à la fois au plus), jamais derrière Siri, le tour, un ordre ou une mission ; une coupure de la page (« Arrêter ») arrête Claude. Sans `stream`, la réponse entière en JSON, comme avant.
- `POST /api/sample/prepare` (0.30.0) : à l'ouverture de la discussion, lance son Claude et lui donne les données (premier message) et l'historique gardé dans le téléphone ; la question suivante n'envoie que la question. `{ok, deja}`. État dans `/api/status` (`page` : questions, reprises, préparées, secours, dernier délai).
- **« Confier à la tâche Claude » (0.11.0)** : `POST /api/tool` avec `Claude Code Remote · fire_trigger`. Le serveur lit lui-même les lignes « Pour = Claude, À faire » du Canal (accès Google direct), Claude rédige sans aucun outil (une réponse JSON), puis le serveur n'écrit que Réponse et Statut de ces lignes (et « Vérifié par Claude » dans Déploiement), après avoir vérifié qu'elles n'ont pas bougé. Aucune ligne : aucun appel à Claude. Une seule tâche à la fois (un appui pendant qu'elle tourne la relance juste après). État : `GET /api/status` (`tache`).
- `/os/` : la nouvelle app (page Jarvis refondue, `essais/jarvis-os-maquette/`), en essai à côté de l'app actuelle (`/`). Sur le serveur, elle charge `jarvis-serveur.js` (vraies données) ; sur GitHub Pages, les données d'exemple.
- Données : `~/.jarvis/state.json` (droits 600 ; jetons stockés en empreinte SHA-256, jamais en clair).
- Installation : `install/setup.sh` (Ubuntu 26.04 ou 24.04 LTS : Node 22, Claude Code, service `jarvis`, Caddy en HTTPS sur `<ip>.sslip.io`, pare-feu). `install/cloud-config.yaml` le lance à la création du serveur.
- Bancs : `node tests/server.test.mjs` (faux Claude `tests/fake-claude.mjs`, faux Google `tests/fake-google.mjs`) ; de bout en bout avec l'app : `jarvis-os/app/tests/e2e-server.cjs`.

Guide pas à pas pour l'iPhone : `docs/jarvis-os.md`, section « Phase 3 ».
